# Документация Magic Oculus

В этой папке находится только актуальная документация. Старые MVP-промпты и
черновые спецификации удалены, потому что они противоречили текущему приложению.

Если вы впервые открыли проект, сначала прочитайте корневой
[README](../README.md), а затем выберите свой раздел ниже.

## Для всех участников

- [ROUTES.md](ROUTES.md) — карта экранов, доступ и навигация.
- [PROJECT_STRUCTURE.md](PROJECT_STRUCTURE.md) — устройство frontend-кода и
  границы слоёв.
- [SECURITY.md](SECURITY.md) — что нельзя коммитить и почему импорт событий
  отключён до появления backend-авторизации.

## Для дизайнера и продакта

- [DESIGNER_START.md](DESIGNER_START.md) — короткая точка входа: где открыть
  сайт и что это за продукт.
- [DESIGN_HANDOFF.md](DESIGN_HANDOFF.md) — пользовательские сценарии, функции
  экранов, обязательные данные и состояния.
- [UI_GUIDELINES.md](UI_GUIDELINES.md) — требования к читаемости, состояниям,
  темам и адаптивности.

## Для frontend-разработчика

## Как читать документацию

Документы не нужно читать подряд целиком. Минимальный маршрут:

1. Корневой [README](../README.md).
2. [ROUTES.md](ROUTES.md).
3. Один профильный документ из разделов выше.

Источники правды в порядке приоритета:

1. текущий код;
2. `src/shared/api/backend-mappers.ts` для ответов backend;
3. `src/shared/api/types.ts` для моделей frontend;
4. профильный документ.

Все документы описывают текущее состояние, если явно не указано, что раздел
является планом или открытой задачей.

## Правило для handoff-документов

Документы для backend, дизайна и других специалистов описывают:

- зачем нужна задача;
- что должно получиться;
- обязательные данные и поведение;
- критерии готовности.

Они не выбирают за исполнителя архитектуру, технологии, внутренний способ
расчёта или конкретное визуальное решение.
