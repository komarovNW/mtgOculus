# Выбор любых колод в матрице матчапов

Статус: новая задача для backend, 06.09.2026. Описанный ниже `deckIds` ещё
не поддерживается работающим API. Документ можно передать разработчику отдельно.

## Что должен получить пользователь

Игрок открывает стандартную матрицу, находит свою колоду по названию и добавляет
её к сравнению, даже если она не входит в топ-40. Колода появляется одновременно
в строке и столбце, с результатами против всех остальных выбранных колод.
Также можно убрать колоду или собрать матрицу из своего списка.

Для этого нужны две доработки существующих ручек:

1. `GET /api/v1/matchups` — матрица по явно заданным ID колод.
2. `GET /api/v1/decks` — серверный поиск названий с пагинацией для выбора колоды.

## Что мешает сейчас

Проверено по актуальной OpenAPI-схеме и запросам к работающему API:

- `/matchups` принимает `top` от 2 до 40, но не принимает список колод;
- запрос с `top=2&deckIds=50` возвращает обычный топ — колоды 5 и 22;
- у `/decks` в схеме нет параметра `search`; запрос с заведомо несуществующим
  названием возвращает непустой обычный список.

Получение топ-40 не даёт данных для произвольной колоды. Существующий ответ
`/matchups` нужно расширить по параметрам выбора, сохранив статистику и структуру.

## 1. Явный состав матрицы: `deckIds`

Добавить необязательный query-параметр `deckIds`: список целочисленных ID
через запятую. Пример ниже иллюстрирует контракт; каждый ID должен существовать
в указанном формате.

```http
GET /api/v1/matchups?formatId=legacy&cityId=moscow&deckIds=5,22,50
```

Правила:

- Без `deckIds` сохраняется текущий режим `top`: 2–40 колод, по умолчанию 15.
- При наличии `deckIds` состав и порядок матрицы определяются только этим
  списком. Популярные колоды автоматически не добавляются и выбранные не
  заменяются. Если одновременно передан `top`, он не применяется.
- Пробелы вокруг ID допустимы. Список должен содержать от 2 до 40 различных
  колод; повторы не допускаются.
- Пустой `deckIds=`, повторные ID, нецелочисленные значения и список вне лимита возвращают
  ошибку 400. Нельзя молча переключаться на режим топа или обрезать список.
- `formatId` остаётся обязательным. Все ID должны существовать и относиться
  к этому формату. Неверные ID возвращаются в ошибке; успешный частичный ответ
  с пропущенными колодами недопустим.
- Действуют все текущие фильтры: `cityId`, `clubId`, `dateFrom`, `dateTo`,
  `tournamentType`. Они ограничивают статистику, а не состав выбранных колод.

Добавление к текущему топу означает новый запрос с ID уже показанных колод
и ID добавляемой колоды. Например, матрица `[5,22]` после добавления 50
запрашивается как `deckIds=5,22,50`. Удаление 22 — как `deckIds=5,50`.
Максимум остаётся 40; для добавления 41-й колоды нужно сначала убрать одну.

## 2. Структура и смысл ответа

Сохранить текущие поля `decks`, `rows`, `appliedFilters` и все поля статистики.
Новый формат ответа не нужен.

- Для `deckIds=5,22,50` порядок `decks` и `rows` — `[5,22,50]`.
- Для N выбранных колод возвращаются N строк и ровно N ячеек в каждой строке.
  `rows[i].deck.id === decks[i].id`; `rows[i].cells[j]` — результат колоды
  `decks[i]` против `decks[j]`, с позиции колоды в строке.
- Возвращаются обе стороны каждого матчапа. Победы одной стороны соответствуют
  поражениям другой, ничьи и число матчей совпадают. При ничьих обратный процент
  не определяется как `100 − winRate`.
- На диагонали `cells[i]` — `null`, число зеркальных матчей — в `mirrorMatches`.
  Зеркала не входят в `overall` и процент побед.
- Если между двумя колодами нет матчей, соответствующие ячейки — `null`.
- `overall` рассчитывается против всего поля по выбранным фильтрам, включая
  колоды за пределами матрицы. Он не является суммой видимых ячеек.
- `metaShare` сохраняет текущую методику и знаменатель полного среза. Доли
  выбранных колод не перенормируются до 100%.
- `matchesCount`, победы, поражения, ничьи, `winRate`, `winRateLow`,
  `winRateHigh`, `isSmallSample` рассчитываются так же, как в режиме топа.
  Проценты и границы интервала остаются в шкале 0–100.
- `appliedFilters` отражает фактически применённые общие фильтры.

**Колода без данных в текущем срезе остаётся в матрице.** Если колода существует
в формате, но не играла в выбранном городе или периоде, возвращаются её ID,
название, `metaShare: 0`, `mirrorMatches: 0`, все `cells: null` и:

```json
{
  "overall": {
    "matchesCount": 0,
    "wins": 0,
    "losses": 0,
    "draws": 0,
    "winRate": null,
    "winRateLow": null,
    "winRateHigh": null,
    "isSmallSample": true
  }
}
```

Если у колоды были только зеркальные матчи, `overall` такой же нулевой,
но `mirrorMatches` и `metaShare` содержат реальные значения. Отсутствие
данных не должно превращаться в винрейт 0% или исчезновение выбранной колоды.

## 3. Поиск колоды: `GET /api/v1/decks`

Добавить и задокументировать `search`, сохранив существующий формат ответа
`count`, `next`, `previous`, `results` и параметры `page`, `page_size`.

```http
GET /api/v1/decks?formatId=legacy&search=tempo&sort=name_asc&page=1&page_size=20
```

Требования:

- Поиск по части названия без учёта регистра, с удалением пробелов по краям.
- `formatId` ограничивает результаты выбранным форматом. Доступны все известные
  колоды формата, включая находящиеся за пределами топ-40.
- Для выбора колоды достаточно `formatId` и поисковой строки. Город, клуб,
  тип события и период в этот запрос не передаются: отсутствие локальных
  матчей не мешает найти колоду и добавить её в матрицу.
- Пустая строка поиска — обычный список колод формата; несовпадающая строка —
  `count: 0`, `results: []`, `next: null`, `previous: null` для первой страницы.
- Поиск применяется до пагинации; `count` соответствует найденным колодам.
- `sort=name_asc` даёт стабильный порядок, при одинаковых названиях — по ID.
- В каждой записи сохраняются как минимум `deck.id`, `deck.name`,
  `deck.archetype`, `deck.colors` и формат. Nullable-значения допустимы.
- Размер страницы 20 поддерживается. Для следующей порции используется `next`;
  интерфейсу не нужно скачивать весь каталог для поиска одного названия.

Это та же задача серверного поиска, которая указана в `BACKEND_DATA_ACCURACY.md`;
отдельный дублирующий endpoint для неё не требуется.

## 4. Ошибки и совместимость

Ответы на ошибки выбора — HTTP 400 в действующей оболочке `error`.
Для нового параметра зафиксировать коды:

| Ситуация | `error.code` |
|---|---|
| Некорректная строка ID, повторы или число колод вне 2–40 | `INVALID_DECK_IDS` |
| Неизвестные ID | `UNKNOWN_DECK_IDS` |
| Колоды другого формата | `DECK_FORMAT_MISMATCH` |

Для неизвестных ID и другого формата дополнительно вернуть список проблемных
ID в `error.deckIds`. Для ошибок существующих фильтров сохраняется действующий
контракт. Пример:

```json
{
  "error": {
    "code": "DECK_FORMAT_MISMATCH",
    "message": "Колода 50 не относится к выбранному формату.",
    "deckIds": [50]
  }
}
```

Запросы без новых параметров должны работать как раньше. Если ответы кэшируются,
результат должен различаться по всем фильтрам, режиму выбора и упорядоченному
списку ID; для режима топа — также по `top`.

## Критерии готовности

- [ ] Прежний запрос без `deckIds` возвращает обычный топ.
- [ ] Колода вне топ-40 находится через `search` и добавляется в матрицу.
- [ ] Произвольные 2, 15 и 40 колод возвращаются строго в заданном порядке;
      одинаковый порядок соблюдается по обеим осям.
- [ ] Для одного и того же набора фильтров и колод данные ручного режима
      совпадают с соответствующими ячейками, `overall` и `metaShare` режима топа.
- [ ] Изменение состава матрицы не меняет `overall` и `metaShare` оставшихся колод.
- [ ] Проверены ничьи, зеркала, малая выборка, отсутствие встреч и колода без
      локальных данных; в пустом срезе выбранные колоды остаются в ответе.
- [ ] Проверены повторные ID, пустая строка, неверные ID, другой формат,
      1 и 41 уникальная колода; нет молчаливого усечения или подмены топом.
- [ ] Поиск учитывает формат и регистр, несуществующее название даёт пустой
      список, пагинация и `count` работают уже после фильтрации.
- [ ] При смене фильтров или порядка ID не возвращается неподходящий ответ из кэша.
- [ ] Матрица приходит одним ответом; для её построения не нужны отдельные
      запросы по каждой колоде. Предоставлены замеры времени и размера ответа
      для 2, 15 и 40 колод на одинаковых фильтрах.
- [ ] OpenAPI обновлена: `deckIds` описан как массив integer в query с
      `style: form`, `explode: false` (CSV), `minItems: 2`, `maxItems: 40`, `uniqueItems: true`;
      добавлены `search`, ошибки и nullable-ячейки/интервалы в примерах ответа.

Для передачи на интеграцию нужны обновлённая Swagger-схема и рабочие примеры:
добавление колоды вне топ-40, пустой срез и ошибка неправильного формата.
