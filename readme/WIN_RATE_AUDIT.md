# Аудит процента побед

## Единое правило frontend

Если API возвращает готовое поле `matchWinRate`, `gameWinRate`, `winRate` или
`deckAWinRate`, frontend показывает его без повторного расчёта. Победы,
поражения и ничьи рядом с процентом также берутся из того же ответа.

Frontend считает процент самостоятельно только для показателей, которых нет в
API и которые явно описаны в интерфейсе как производные.

## Явные производные показатели

- Рейтинг игроков на главной использует скорректированный процент побед. Личный
  процент и взвешенное среднее поля строятся из серверного `matchWinRate`, а
  frontend применяет только раскрытую рядом с таблицей корректировку выборки.
- История по месяцам, оппоненты и матчапы колоды в профиле игрока считаются из
  загруженной истории матчей: готовых агрегатов для них API не возвращает.
- В блоке частых матчапов процент колоды A приходит как `deckAWinRate`, а процент
  колоды B и доля ничьих восстанавливаются из результата пары, потому что
  отдельных полей для них в ответе нет.
- Доли поля, доли игроков и другие показатели состава выборки не являются
  процентом побед и считаются отдельно либо берутся из одноимённых полей API.

## Обнаруженное расхождение backend

На живом API одинаковое название поля пока не гарантирует одинаковую формулу.
Например, в Pauper игрок с результатом `3-0-1` приходит с
`matchWinRate: 100`, то есть ничья не входит в знаменатель. Для колод BYE и
ничьи обрабатываются иначе. Frontend не маскирует это собственным пересчётом:
исправление должно быть единым на backend для всех перечисленных ответов.

Целевая формула уже зафиксирована в backend-контракте:

```text
matchWinRate = wins / (wins + losses + draws) * 100
```

BYE не должен входить ни в `wins`, ни в знаменатель этой формулы. После
исправления backend все обычные экраны автоматически начнут показывать
одинаковый результат без отдельных изменений frontend.
