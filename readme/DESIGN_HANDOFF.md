# Требования к дизайну Magic Oculus

## Цель

Нужно обновить интерфейс публичного сервиса статистики Magic: The Gathering.
Дизайн должен помочь быстро читать данные и переходить между связанными
событиями, игроками и колодами.

Этот документ описывает функции и обязательные состояния. Конкретные визуальные
решения остаются за дизайнером.

Текущий сайт:
[komarovnw-mtgoculus-c126.twc1.net](https://komarovnw-mtgoculus-c126.twc1.net/).

## Пользователь

Основной пользователь — игрок Magic: The Gathering. Он хочет:

- понять состояние метагейма;
- найти прошедшее событие;
- посмотреть результаты игрока;
- сравнить игроков или колоды;
- изучить личные матчи и матчапы колод.

Добавить результаты сыгранного события может любой пользователь. Отдельной роли
организатора и авторизации сейчас нет.

## Навигация

Основные разделы:

- Главная;
- Дейлики;
- Турниры;
- Игроки;
- Колоды.
- Добавить.

Дополнительно:

- переключатель светлой и тёмной темы;
- мобильное меню;
- ссылка на текущую версию и страницу `Что нового` в футере.

Выбранные фильтры сохраняются при переходе между статистическими разделами.
Скрытый дайджест и `Что нового` фильтры не используют.

## Общие фильтры

Поля:

- город;
- клуб;
- формат;
- тип события;
- дата от;
- дата до.

Поведение:

- список клубов зависит от города;
- при смене города выбранный клуб сбрасывается;
- фильтры меняют все данные текущего экрана;
- активный срез должен быть понятен после закрытия блока фильтров;
- есть сброс;
- на странице дейликов тип всегда `daily`;
- на странице турниров тип всегда `tournament`.

## Главная

Задача экрана: дать общую картину по выбранным фильтрам.

Обязательные данные:

- количество событий;
- количество участий;
- количество уникальных игроков;
- количество матчей;
- количество уникальных колод;
- краткие ключевые выводы;
- популярность колод;
- результативность колод;
- лучшие игроки;
- частые матчапы;
- последние события.

Точные значения должны оставаться доступными, даже если часть информации
показана графиком.

## Дейлики и турниры

Это два отдельных списка с одинаковым набором возможностей.

Обязательные элементы:

- фильтры;
- количество найденных событий;
- краткий ориентир;
- таблица;
- дозагрузка;
- прогресс `Показано X из Y`.

Строка события содержит:

- дату;
- название;
- клуб;
- формат;
- количество игроков;
- победителя.

В дейликах победитель показывается вместе с колодой. В списке крупных турниров
дополнительно доступны количество раундов и сыгранных матчей.

Разница между дейликами и турнирами должна быть понятна по контексту экрана.

## Событие

В верхней части нужны:

- название;
- тип события;
- дата;
- город и клуб;
- формат;
- количество игроков;
- количество раундов;
- количество матчей;
- победитель.

Разделы страницы:

### Стендинги

- итоговое место;
- игрок;
- колода;
- результат;
- очки;
- OMW, GW и OGW.

### Раунды

- номер раунда и стол;
- оба игрока;
- обе колоды;
- счёт;
- победитель.

### Колоды

- игрок;
- колода;
- место;
- итоговый результат.

### Метагейм

- колода;
- количество игроков;
- доля метагейма;
- графическое представление популярности.

## Список игроков

Обязательные элементы:

- поиск по имени;
- общие фильтры;
- сортировка;
- дозагрузка;
- прогресс `Показано X из Y`;
- краткий ориентир.

Строка игрока содержит:

- имя;
- количество турниров;
- количество матчей;
- record;
- winrate;
- любимую колоду;
- предупреждение о малой выборке при необходимости.

## Игрок

Общая статистика:

- турниры;
- первые места — сколько раз игрок занимал топ-1;
- известные матчи, включая BYE;
- record по известным матчам, включая BYE;
- winrate по известным матчам, включая BYE;
- количество разных колод.

Если подробностей матча не хватает, frontend не пытается восстановить его
результат. Такая запись исключается из статистики, а количество исключённых
матчей показывается рядом.

Исключение — BYE, пропущенный backend в истории конкретного события: frontend
может восстановить его только по однозначно отсутствующему номеру раунда и
итоговому record. Полностью отсутствующую историю события frontend не угадывает.

На личной странице используется мягкий порог: 5 матчей минимум в 2 событиях.
Он нужен для показа персональной статистики и не меняет более строгий порог
20 матчей в 5 турнирах в общем рейтинге игроков.

Отдельный блок профиля содержит:

- период доступной истории;
- любимую колоду по количеству известных матчей, включая BYE;
- любимый формат за всю историю, независимо от активного фильтра формата;
- самого частого оппонента.

Лучший и худший личный winrate против оппонентов не показываются.

Месячный график переключается между количеством турниров и процентом побед.
Размер выборки и record месяца доступны в подсказке.
По умолчанию график показывает последний календарный год, который есть в
данных. Переключатель «Вся история» возвращает более ранние годы.

Разделы страницы:

### Турниры игрока

- событие и дата;
- колода;
- итог в формате `место из количества участников`;
- результат;

### Колоды игрока

- колода;
- события;
- матчи;
- record;
- winrate;
- малая выборка.

### История матчей

- матчи сгруппированы по отдельным дейликам и турнирам;
- в заголовке группы показаны название, тип события, дата, клуб и формат;
- рядом показан record игрока только в рамках этого события;
- внутри остаются раунд, колоды, оппонент, результат и счёт;
- BYE показывается отдельной строкой вместо ссылки на оппонента;
- дозагрузка открывает следующие события целиком и не разрывает один дейлик
  между страницами.

Все три списка дозагружаются. Если нет матчей с известным оппонентом, нужно
отдельное пустое состояние.

## Список колод

Обязательные элементы:

- поиск по названию;
- общие фильтры;
- сортировка;
- дозагрузка;
- прогресс `Показано X из Y`;
- краткий ориентир.

Показываются все колоды. Небольшое количество матчей отмечается как малая
выборка, но не скрывает строку.

Строка колоды содержит:

- название и цвета, если они известны;
- формат;
- количество событий;
- количество участий;
- количество матчей;
- record;
- winrate;
- малую выборку.

## Колода

Общая статистика:

- события;
- участия;
- уникальные игроки;
- матчи;
- record;
- winrate;
- доля метагейма;
- формат и цвета;
- малая выборка.

Ниже общей статистики показываются:

- самый активный игрок;
- самый частый матчап;
- лучший и худший матчап только при достаточной выборке;
- пояснение покрытия известных колод оппонентов;
- месячная динамика участий и процента побед; количество матчей остаётся в
  подсказке как размер выборки.

Разделы страницы:

- результаты по событиям;
- игроки на этой колоде;
- матчапы против других колод.

Результат в событии показывает итоговое место вместе с количеством участников,
например `5 из 32`. Очки не показываются.

В таблице игроков нет лучшего места. По умолчанию игроки упорядочены по
количеству матчей.

Матчап содержит количество встреч, долю известных встреч, record и winrate.
Для сравнения матчапов требуется минимум 10 матчей; зеркальные матчи не
участвуют в выборе лучшего и худшего матчапа.

## Дайджест

Сейчас это экран-заглушка `В разработке`, скрытый из основной навигации.

В будущем здесь будут ежемесячные статьи с выводами по статистике. Полноценный
экран статей пока проектировать не требуется.

## Что нового

Вспомогательная страница, доступная по версии в футере.

Она содержит:

- текущую версию;
- статус версии;
- описание изменений по категориям;
- предыдущие релизы.

## Добавить

Публичная форма добавления сыгранного дейлика или турнира.

Поля:

- дата;
- город;
- клуб;
- тип события;
- формат;
- ссылка на Aetherhub;
- список игроков и колод.

Нужны состояния:

- незаполненная форма;
- понятная отметка обязательных полей;
- итоговая сводка перед отправкой;
- определённый режим списка и количество непустых строк;
- ошибки проверки;
- ошибка загрузки зависимого списка клубов с повторной попыткой;
- отправка;
- ошибка backend;
- успешное добавление;
- предупреждения после успешного добавления.

Страница публичная и не должна выглядеть как административный или служебный
раздел. Подробная инструкция и ссылки на страницы клубов в Aetherhub остаются
доступны на самой странице.

## Обязательные состояния

Для основных экранов нужны:

- первая загрузка;
- дозагрузка;
- пустой результат;
- пустой поиск;
- ошибка первой загрузки с retry;
- ошибка дозагрузки без исчезновения показанных данных;
- disabled-состояния зависимых полей;
- малая выборка;
- отсутствующий победитель, колода, цвет или место;
- длинные имена и большие значения.

## Адаптивность

Нужны варианты:

- desktop;
- tablet;
- mobile.

На всех размерах должны оставаться доступными:

- основные действия;
- фильтры и активный срез;
- переходы между сущностями;
- точные показатели таблиц;
- сортировка;
- дозагрузка.

## Термины

- Событие — общее название дейлика или крупного турнира.
- Дейлик — регулярное локальное событие.
- Турнир — более крупное или специальное событие.
- Record `3-1-0` — победы, поражения и ничьи по матчам.
- Участие — один выход игрока с колодой на событие.
- Winrate — доля побед среди всех матчей, включая ничьи в общем количестве.
- Малая выборка — предупреждение о недостаточном количестве матчей; данные при
  этом не скрываются.
- OMW, GW и OGW — турнирные тайбрейки.

## Первый комплект макетов

Нужны:

1. навигация на desktop и mobile;
2. главная на desktop и mobile;
3. один список на примере игроков или колод;
4. страница игрока;
5. фильтры и отображение активного среза;
6. loading, empty, error и дозагрузка;
7. базовые компоненты, типографика и цвета.

## Не входит в задачу

- регистрация и профиль;
- deck builder;
- каталог карт;
- магазин и оплата;
- регистрация на турниры;
- live pairings;
- социальная лента;
- отдельный экран сравнения игроков;
- отдельный matchup explorer.
