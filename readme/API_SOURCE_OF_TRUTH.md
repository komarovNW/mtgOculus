# API как источник статистики

Актуализировано по OpenAPI-схеме `magicOculus API 1.0.0` от 21 октября
2026 года. Копия схемы хранится в [`openapi.yaml`](./openapi.yaml).

## Правило интеграции

Если API возвращает готовый агрегат, интерфейс использует его без повторного
расчёта. Это относится к количеству матчей, победам, поражениям, ничьим,
винрейту, BYE и признаку малой выборки.

Фронтенд может считать показатель только когда соответствующего поля или
агрегата нет в контракте. Такой расчёт должен использовать серверные исходные
данные и не подменять серверную сводку.

## Что берём с сервера

| Раздел | Серверные данные |
| --- | --- |
| Главная `/home` | общая сводка, метагейм, эффективность колод, лучшие игроки, популярные матчапы |
| Игроки `/players` | `playedMatchesCount`, `byesCount`, `playedWins`, record, `matchWinRate`, `isSmallSample` |
| Игрок `/players/{id}` | та же сводка, game record/winrate, колоды игрока и их серверные показатели |
| Колоды `/decks` | сыгранные матчи, BYE, record, `matchWinRate`, `isSmallSample` |
| Колода `/decks/{id}` | summary, показатели игроков и готовые матчапы с `winRate` и `isSmallSample` |
| Турниры `/tournaments` | `roundsCount`, `pairingsCount`, `playedMatchesCount`, `byesCount`, `league`, `sourceUrl` |
| Матрица `/matchups` | все ячейки, общий результат, винрейт, доверительный интервал и малая выборка |

Для игроков `matchWins` может включать техническую победу BYE. Согласованная
пара для отображения record и винрейта против соперников — `playedWins` и
`playedMatchesCount`; готовый `matchWinRate` всегда берётся с сервера.

## Что пока рассчитывает фронтенд

- месячную динамику игрока и колоды — API не отдаёт временные ряды;
- статистику игрока против конкретных оппонентов;
- матчапы конкретной колоды конкретного игрока;
- долю любимой колоды и производные рейтинги/медианы для обзорных блоков;
- число полностью сыгранных турниров без поражений и ничьих — составляется из
  record игрока и количества раундов турнира;
- долю метагейма на странице одной колоды — в detail-ответе отдельного поля нет.

Эти значения нельзя использовать вместо одноимённых серверных агрегатов, если
они появятся в следующей версии API.

## Найденные и исправленные расхождения

- профиль игрока больше не пересчитывает общий винрейт по `recentMatches` и не
  включает BYE в его знаменатель;
- record игрока и его колод использует `playedWins`, а не технические победы;
- отметка «Малая выборка» использует серверный `isSmallSample`;
- сводка турнира использует серверные `roundsCount`, `pairingsCount`,
  `playedMatchesCount` и `byesCount`, а не длину загруженных массивов;
- ссылка на источник турнира читается из актуального поля `sourceUrl`;
- мапперы больше не теряют `playedWins`, played/BYE-счётчики, `league` и
  `sourceUrl`.


## Турниры с плей-офф — контракт от 21 октября 2026

- В списке и деталях `playoffSize` — размер топа, `null` — топа не было;
  отсутствие поля у дейлика не означает ошибку. `winner` берётся с сервера.
- `rank` — итоговое место, включая топ. Порядок стендингов сохраняется как в API.
  `swissRank` — отдельное справочное место. Record, очки и тайбрейки стендингов — швейцарка.
- `rounds` содержит только швейцарку. `playoff` содержит стадии от большей к финалу;
  порядок матчей внутри стадии сохраняется. Для турнира без топа массив пуст.
- `recentMatches[].playoffTopN` отличает стадии топа от швейцарки (`null`).
  Сортировка учитывает стадию даже при совпадающих номерах раундов.
- Серверные агрегаты игроков, колод и матчапов уже включают плей-офф;
  добавлять к ним матчи топа повторно нельзя.
- Турнир можно необязательно связать со свободной строкой плана отбора через
  `leagueQualifierId`. Варианты загружаются из `/leagues/qualifiers/options`.

Проверено локально по присланному контракту и тестовым ответам. Прямой GET к
настроенному production API 21 октября завершился тайм-аутом; проверка актуальных
живых ответов и реального импорта остаётся отдельным этапом интеграции.
