# Таблица лиги: handoff после обновления backend

Статус на 2026-09-17: **контракт развёрнут на backend и интегрирован во
frontend**.

Таблица строится по `columns`, зоны берутся из `zone`, а персональная страница
лиги открывается по `/leagues/:id`. Клиентская настройка порядка удалена:
frontend показывает официальный порядок конкретной лиги.

## Согласованный контракт

`GET /api/v1/leagues/<id>` только расширяется: существующие поля не меняются.

```json
{
  "sort": ["tournamentPoints", "xZeroCount"],
  "columns": [
    {
      "position": 1,
      "key": "tournamentPoints",
      "label": "Турнирные очки"
    },
    {
      "position": 2,
      "key": "xZeroCount",
      "label": "Турниров X-0"
    }
  ],
  "cutoffs": {
    "qualify": 8,
    "reserve": 10
  },
  "standings": [
    {
      "leagueRank": 1,
      "rank": 1,
      "player": {
        "id": 7,
        "name": "Иванов"
      },
      "tournamentPoints": 15,
      "xZeroCount": 1,
      "xOneCount": 2,
      "zone": "qualify"
    }
  ]
}
```

Обязательное поведение backend:

- `sort` содержит фактически применённый порядок показателей;
- `columns` приходит в фактически применённом порядке: из `?sort=`, иначе из
  настройки лиги;
- `columns.position` начинается с `1`, позиции идут подряд без пропусков;
- `columns.label` берётся из единого backend-реестра показателей;
- `cutoffs` содержит только заданные границы, без границ возвращается `{}`;
- `xZeroCount` и `xOneCount` присутствуют в каждой строке `standings`;
- `zone` присутствует всегда и принимает `"qualify"`, `"reserve"` или `null`;
- `zone` рассчитывается backend по `leagueRank`;
- `?sort=` принимает новые ключи, а enum OpenAPI строится из того же реестра;
- при полном равенстве показателей порядок определяется именем игрока, не `id`.

## Источники правды для frontend

- `sort` определяет расчёт и порядок мест;
- `columns` определяет состав, порядок и подписи колонок таблицы;
- `zone` определяет подсветку строки;
- `cutoffs` используется только для пояснения границ и легенды;
- frontend не пересчитывает порядок, места или зоны самостоятельно.

Таблица должна строиться динамически по `columns`. Это позволяет разным лигам
показывать разные тай-брейки без отдельных условий и подписей во frontend.

## Названия новых показателей

Рекомендуемые понятные подписи:

- `xZeroCount` — «Все матчи выиграны»;
- `xOneCount` — «Кроме одного матча».

В подсказках нужно раскрыть точный смысл:

- `xZeroCount` — «Количество турниров с результатом X-0»;
- `xOneCount` — «Количество турниров с результатом X-1 или X-0-1».

Формулировку «Выиграл все кроме 1» без слова «матча» не используем: она
двусмысленна.

Окончательные подписи таблицы всё равно приходят в `columns.label` с backend.
Frontend не должен заменять их своим словарём.

## Зоны таблицы

- `qualify` — проходит в основной состав;
- `reserve` — резерв;
- `null` — строка без зональной подсветки.

Подсветка не должна быть единственным способом различить зоны: рядом с таблицей
нужна компактная текстовая легенда. Если `cutoffs` пустой, легенда и подсветка
зон не показываются.

## Маршруты

Для каждой лиги нужна персональная ссылка:

- `/leagues` — список или выбор лиги;
- `/leagues/:id` — страница конкретной лиги;
- старый `/leagues?leagueId=<id>` после перехода можно сохранить через редирект
  на персональный маршрут.

## Ручное изменение порядка

Рекомендуемое продуктовое решение — показывать официальный порядок выбранной
лиги и убрать пользовательскую настройку «Изменить порядок». Backend уже знает
правила конкретной лиги, а разные лиги могут иметь разные наборы тай-брейков.

Если ручную сортировку решим сохранить, текущего `columns` недостаточно:
frontend видит только применённые показатели, но не полный список допустимых
вариантов. Тогда backend должен дополнительно вернуть runtime-список вроде
`sortOptions` с `key` и `label`. OpenAPI enum нельзя использовать как источник
данных работающего интерфейса.

## Реализовано на frontend

1. Модели `LeagueDetails` и `LeagueStanding` расширены новыми полями.
2. Жёстко заданные показатели удалены, колонки строятся по `columns`.
3. Значение строки безопасно читается по `column.key`.
4. Строки и легенда отображаются по `zone` и `cutoffs`.
5. Добавлен маршрут `/leagues/:id`, старый URL с `leagueId` перенаправляется.
6. Ручная сортировка удалена; показывается официальный порядок backend.
7. Контракт и интерфейс покрыты тестами.
