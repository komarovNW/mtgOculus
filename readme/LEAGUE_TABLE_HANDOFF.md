# Таблица и отбор лиги

Актуальный контракт `GET /api/v1/leagues/{id}` от 21 октября 2026 года.

## Таблица

Backend задаёт порядок строк в `standings` и порядок динамических колонок в
`columns`. Frontend не рассчитывает проходные зоны и не раздаёт места в финал.

Из ответа удалены:

- `cutoffs`;
- `prequalified`;
- `standings[].zone`;
- `standings[].prequalifiedComment`.

Поэтому в таблице нет подсветки проходной и резервной зон, статусов «Прошёл» и
блока «Уже отобрались». Таблица показывает рейтинг и серверные показатели.

## Отбор в финал

Поле `qualification` содержит правила отбора в порядке, заданном backend:

```ts
type LeagueQualificationBlock = {
  title: string | null;
  slots: number;
  seats: Array<{
    player: { id: number; name: string } | null;
    comment: string | null;
  }>;
};
```

Правила отображения:

- общее число мест — сумма `slots` всех блоков;
- блоки и места внутри них не пересортировываются;
- `title: null` показывается как `TBA`;
- `player: null` показывается как `TBA`;
- `comment` выводится рядом с игроком или свободным местом;
- число элементов `seats` равно `slots`.

Backend сам исключает повторное попадание уже прошедшего игрока в следующие
блоки. Frontend не выводит вычисленные статусы «Место обеспечено» и «Проходит
сейчас».

## Связь с импортом турнира

`GET /api/v1/leagues/qualifiers/options` возвращает ещё не привязанные
отборочные турниры. При импорте обычного турнира или турнира Melee.gg можно
передать необязательный `leagueQualifierId`.
