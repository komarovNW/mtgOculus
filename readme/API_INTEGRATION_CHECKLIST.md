# Проверка интеграции с API

Чеклист используется после изменения backend-контракта, фильтров, mapper-функций
или окружения.

## Окружение

- [ ] В `.env.local` задан корректный `VITE_API_BASE_URL`.
- [ ] Base URL заканчивается на `/api/v1` или ведёт на эквивалентный API prefix.
- [ ] Production-сборка получает `VITE_API_BASE_URL` из окружения хостинга.
- [ ] CORS разрешает frontend origin.
- [ ] Все запросы проходят через `src/shared/api/client.ts`.

Mock API и mock-auth в проекте отсутствуют.

## Общие правила

- [ ] Даты приходят в формате `YYYY-MM-DD`.
- [ ] Проценты приходят в диапазоне `0..100`.
- [ ] ID игрока, колоды и события стабильны.
- [ ] Nullable-поля не заменяются строками `"null"` или `"undefined"`.
- [ ] Ошибка содержит человекочитаемое сообщение.
- [ ] Loading, empty, error и retry работают на основных страницах.

## Справочники

- [ ] `GET /cities` возвращает массив городов.
- [ ] `GET /cities/{cityId}/clubs` возвращает массив клубов выбранного города.
- [ ] `GET /formats` возвращает массив форматов.
- [ ] Значения `moscow` и `legacy` существуют, пока они используются как defaults.
- [ ] При смене города выбранный клуб сбрасывается.

## Главная

- [ ] `GET /home` применяет все переданные dashboard-фильтры.
- [ ] Summary, события, метагейм, колоды, игроки и матчапы отображаются.
- [ ] Ссылки на сущности ведут на существующие detail pages.
- [ ] Пустые секции не ломают остальную страницу.

## Дайджест

Backend-интеграции пока нет.

- [ ] `/digest` открывается без запроса к API.
- [ ] В основной навигации нет ссылки `Дайджест`.
- [ ] При прямом переходе в дайджест dashboard query-параметры не влияют на экран.
- [ ] Placeholder ясно сообщает, что экран находится в разработке.

## Списки

Для `GET /tournaments`, `GET /players` и `GET /decks`:

- [ ] backend принимает `page` и `page_size`;
- [ ] ответ использует `count`, `next`, `previous`, `results`;
- [ ] `next` становится `null` на последней странице;
- [ ] повторная дозагрузка не создаёт дубликаты;
- [ ] смена фильтра, поиска или сортировки сбрасывает список на первую страницу;
- [ ] `Показано X из Y` соответствует `results` и `count`.
- [ ] Смена фильтра или страницы отменяет ненужные GET и дальнейший полный обход.
- [ ] Если backend ограничил `page_size`, полный обход продолжает загрузку по `next`.
- [ ] Ошибка одной из страниц не превращается в успешную частичную сводку.
- [ ] Ввод имени игрока не запускает запрос на каждую букву; старые строки не
      показываются как результат нового поиска.
- [ ] Поиск колоды не запускает неиспользуемый серверный запрос, пока действует
      клиентский обходной поиск.

Дополнительно:

- [ ] `/dailies` отправляет `tournamentType=daily`;
- [ ] `/tournaments` отправляет `tournamentType=tournament`;
- [ ] игроки поддерживают `search`, `sort` и `order`;
- [ ] колоды поддерживают `search` и `sort`;
- [ ] список колод не отсекает строки с малым числом матчей.

## Detail pages

- [ ] `GET /tournaments/{id}` возвращает стендинги, раунды, колоды и метагейм.
- [ ] BYE не создаёт сломанную ссылку на игрока.
- [ ] `GET /players/{id}` возвращает события, колоды и историю матчей.
- [ ] В событии каждого матча есть `type`, чтобы разделять дейлики и турниры.
- [ ] В событии каждого матча есть клуб.
- [ ] BYE присутствует в истории игрока с `opponent: null` и `isBye: true`.
- [ ] Пропущенный раунд не превращается на frontend в победу BYE.
- [ ] Запись с `opponent: null` без `isBye: true` считается неизвестной, а не
      BYE, и не участвует в статистике.
- [ ] Сводка игрока позволяет получить точное количество турниров, в которых
      игрок доиграл все раунды без поражений и ничьих, независимо от места.
- [ ] Любимый формат игрока рассчитывается по полной карьере, частый оппонент —
      по истории текущего среза.
- [ ] `GET /decks/{id}` возвращает результаты, игроков и матчапы.
- [ ] 404 от backend превращается в понятное состояние страницы.

## Матрица матчапов

- [ ] `/matchups` доступен из меню и по прямой ссылке.
- [ ] `GET /matchups` принимает `formatId` (обязательный), `cityId`, `clubId`,
      `tournamentType`, `dateFrom`, `dateTo`, `top` (2–40, default 15).
- [ ] При незаданном формате и обратном порядке дат статистика не запрашивается.
- [ ] Изменение `top` применяется по кнопке, сохраняется в URL и восстанавливается
      при переходе назад; набираемые промежуточные числа не отправляются.
- [ ] Быстрые периоды 30/90/180/365 дней обновляют обе даты одним действием,
      включая сегодня и ровно N календарных дней; остальные фильтры сохраняются.
- [ ] «Всё время» очищает только даты. Ручной диапазон отображается как
      «Свой период»; значения в общих фильтрах и активный быстрый период согласованы.
- [ ] Даты из ссылки не перезаписываются при входе; конкретные границы сохраняются
      при переходе назад, в ссылках на колоды и после применения размера матрицы.
- [ ] Строки сопоставляются по ID, `cells[i]` соответствует `decks[i]` даже при
      другом порядке строк в ответе. Ошибка размеров не даёт неверную матрицу.
- [ ] `null` и ноль сыгранных матчей показаны как `—`; настоящий винрейт 0% сохранён.
- [ ] Диагональ показывает `mirrorMatches`, общий столбец — серверный `overall`.
- [ ] Ничьи не заменяются на поражения; обратный винрейт не вычисляется как `100 − winRate`.
- [ ] `isSmallSample`, record и интервал доступны в подсказке по наведению,
      фокусу и нажатию. Escape закрывает её; стрелки перемещают между ячейками.
- [ ] Кэш и отмена работают при смене фильтров; матрица не догружает каждую колоду.
- [ ] Таблица 40×40 разворачивается на полную высоту без внутренней вертикальной
      прокрутки; горизонтальная прокрутка сохраняет названия строк слева.
      Мобильный экран и обе темы сохраняют читаемость.

## Добавление события

- [ ] `/admin/tournaments/create` открывается без авторизации.
- [ ] `POST /admin/tournaments/import` доступен без авторизации.
- [ ] Endpoint принимает `multipart/form-data`.
- [ ] Поддерживаются дейлики и турниры.
- [ ] Backend валидирует поля, ссылку и список колод.
- [ ] Ограничены размер и частота запросов.
- [ ] Успех возвращает созданное событие и необязательные предупреждения.
- [ ] Ошибка импорта возвращает массивы `errors` и `warnings` с понятными
      `message`, `code` и `source`.
- [ ] Frontend показывает все сообщения backend, а не только общий текст ошибки.
- [ ] После успеха кэш статистики инвалидируется; при переходе к спискам новые
      результаты не скрыты за старой сводкой.

## Перед релизом

```bash
npm run typecheck
npm run lint
npm run test
npm run build
```

- [ ] Главная открывается с production API.
- [ ] `/digest` открывается по прямой production-ссылке.
- [ ] Прямая ссылка на detail page работает после обновления браузера.
- [ ] Дейлики и турниры не смешиваются.
- [ ] Поиск и `Показать ещё` работают у игроков и колод.
- [ ] Светлая и тёмная темы не ломают таблицы и фильтры.
