## Сохранённое описание реализации

Статус: для осенней лиги Портала распределение финальных мест рассчитывается
на frontend из существующих `standings` и `prequalified`. Новые поля backend
не обязательны. Чистая функция: `src/entities/league/lib/qualification.ts`.
Готовый серверный `qualification`, если он присутствует, сохраняет приоритет.

Локальный регламент применяется только к лиге клуба «Портал» / «Portal»,
с «осенн» в названии, началом 01.09 и окончанием в ноябре. Для остальных лиг
сохраняется прежнее поведение. Это явное ограничение области действия,
а не универсальные правила всех лиг.

Уже прошедшие берутся из `prequalified` и строк `zone: prequalified`,
объединяются по ID игрока. Месяц Store Championship берётся из существующего
комментария: «сентябрь», «ноябрь», September / November, даты DD.MM / DD/MM
или YYYY-MM-DD. Для повторного попадания нужно сохранить оба основания:
две записи либо обе даты/месяца в комментарии. Зеркальная запись одного
основания в списке и строке таблицы не даёт дополнительного слота.
Если месяц не указан, место всё равно обеспечено, но Store Championship
отображаются общим блоком; повтор без обоих оснований не предполагается.
Имена и результаты игроков в исходники не зашиваются.

## Интерфейс

По умолчанию открыт режим «Очки и статистика»: турнирные очки, бонусные очки,
посещения. X−1 / X−0−1 виден в режиме отбора и в подробностях игрока.
X−0 не выводится, поскольку не участвует в отборе этой лиги. Поиск по имени не меняет официальные места.
В деталях игрока видны дополнительный показатель, число зачтённых турниров
(только если отличается от посещений), начисления
по правилам, ручные бонусы и результаты каждого турнира. Очки лиги и бонусы
показываются отдельно и не складываются в один показатель.

В режиме «Отбор в финал» отображаются группы слотов и основание прохода каждого
игрока. Подробные позиции по путям отбора раскрываются в строке игрока;
правила начисления свёрнуты в шапке. Для лиг без применимого локального регламента и без серверного расчёта
показываются известные предварительно квалифицированные игроки и старые зоны рейтинга. `zone: null` не означает
«не проходит». Участники из `prequalified` показываются и без участия в дейликах.

## Модель результата (также поддерживается как расширение API)

Необязательное поле `bonusPointsLabel` задаёт название бонусной валюты, например
`Podval Points`. Без него используется подпись колонки `bonusPoints`, затем
«Бонусные очки». Не следует переименовывать бонусы всех лиг в Podval Points.

Необязательное поле `qualification` в ответе лиги:

```json
{
  "totalSlots": 16,
  "groups": [
    {
      "key": "league_points",
      "label": "Очки лиги",
      "slots": 5,
      "description": "4 места + 1 за повторную квалификацию на Store Championship",
      "entries": [
        {
          "player": { "id": "example-player", "name": "Тестовый игрок" },
          "status": "provisional",
          "reason": "4-е из 5 мест после исключения уже прошедших"
        }
      ]
    }
  ]
}
```

Пример показывает одну группу; реальный ответ должен содержать все группы в
порядке распределения. `slots` — фактическая квота с учётом переноса, сумма
квот равна `totalSlots`. `entries` не содержит повторов между группами.
Статусы: `confirmed` — место обеспечено; `provisional` — проходит сейчас.
Для ещё не сыгранного Store Championship возвращается пустой `entries`, а
`description` объясняет, когда определятся участники. Незанятые слоты нельзя
временно распределять в других категориях.

Необязательное поле `qualification` у каждого элемента `standings`:

```json
{
  "status": "provisional",
  "reason": "Проходит по Podval Points",
  "paths": [
    { "label": "Очки лиги", "description": "5-й в отборе, проходят 4; до границы 3 очка" },
    { "label": "Podval Points", "description": "2-й в отборе, проходят 3" }
  ]
}
```

Статусы: `confirmed`, `provisional`, `outside`, `unresolved`. Последний означает
неразрешённое равенство по всем предусмотренным регламентом показателям.
`reason` объясняет основание статуса, `paths` — положение на остальных путях.
Позиции и разрывы считаются с учётом исключений на каждом этапе.
Нельзя обещать квалификацию за определённое число будущих побед.

Локальная функция строит группы и оценки строк из одного снимка исходных
данных. Она не меняет очки, посещения или официальный порядок строк.
Если сервер отдаёт готовый расчёт, он тоже должен быть полным и согласованным.

## Алгоритм осенней лиги Портала

1. Обеспеченные места: топ-4 сентябрьского и топ-4 ноябрьского Store Championship.
2. Повторное попадание одного игрока в обе четвёрки увеличивает квоту отбора
   по очкам на один слот за каждый такой повтор.
3. Отбор по очкам лиги: 4 + перенесённые слоты, исключая уже прошедших.
4. Отбор по Podval Points: 3 места среди оставшихся.
5. Отбор по посещениям: 1 место среди оставшихся.

Уточнения организатора от 11.10.2026 (предоставлены пользователем):

- Порядок категорий и перенос одного слота за каждого повторного участника
  двух топ-4 подтверждены.
- Очки лиги → Podval Points → X−1 / X−0−1 (исходный регламент).
- Podval Points → **очки лиги** → X−1 / X−0−1. Организатор подтвердил,
  что очки лиги сравниваются раньше дополнительного показателя.
- Посещения → **очки лиги** → **Podval Points** (последующее уточнение
  пользователя). При равенстве всех трёх — решение организатора; X−1 / X−0−1
  в эту цепочку не добавлен.
- Полное равенство на границе решает организатор. Алфавит, ID и порядок
  исходных строк не используются для выдачи места.

При неразрешённом равенстве на границе категория выдаёт только бесспорные
места перед группой равенства. Следующие категории зависят от того, кого
исключить, поэтому их распределение помечается ожидающим решения. Остальные
игроки получают `unresolved`, а не необоснованный отказ или проход.
Это консервативное представление: перебор всех возможных решений равенства
для поиска дополнительных гарантированных проходов не выполняется.

## Подтверждённые правила исходной статистики

- Период 01.09–29.11 включительно; зачётные дейлики вторника и пятницы,
  без ограничения количества лучших турниров. Победа — 3, ничья — 1.
- В посещения входят только зачётные дейлики, включая участие с дропом.
  Store Championship и другие турниры не входят.
- X−1 и X−0−1 складываются в один показатель только по зачётным дейликам.
  По делегированному пользователем решению учитываются только завершённые
  дейлики: результат с дропом не увеличивает `xOneCount`, даже если
  промежуточный результат имеет вид X−1 или X−0−1. BYE считается победой
  и не препятствует завершению турнира. Это выбранное правило продукта,
  а не дословное подтверждение организатора.
- Podval Points начисляются один раз за турнир за **точный** результат:
  12→4, 10→3; во вторник также 9→3 и 7→2. Пороговые правила не суммируются.
- Варианты 12→4 и 10→3 действуют и во вторник, если будет четыре раунда.
- BYE входит в победы. Дроп без поражений не даёт Podval Points.
- При отказе от финала слот переходит следующему по **тому же основанию**.

## Граница текущей реализации и оставшиеся вопросы

Frontend исправляет сравнение показателей, но получает готовые суммы из API:
`tournamentPoints`, `bonusPoints`, `tournamentsPlayed`, `xOneCount`. В контракте
участия нет признака дропа, полного результата W/L/D и BYE. Поэтому соблюдение
правил начислений, посещений и дропов нужно проверить на backend; локальная
функция распределения мест не может исправить неверные исходные суммы.

Отказы и выбор организатора при равенстве пока не представлены входными
данными и не обрабатываются автоматически. Для отказа нужны отказавшийся
игрок, исходная категория слота и список кандидатов этой категории; простое
удаление игрока с полным перерасчётом всех квот не заменяет это правило.

Решение по X−1 / X−0−1 с дропом принято: исключать из дополнительного
показателя, но сохранять посещение и заработанные очки лиги. Применение этого
фильтра в реальной статистике остаётся backend-задачей: API должен возвращать
`xOneCount` только по завершённым зачётным дейликам. По числу очков или полю
`counted` определять дроп нельзя (`counted` описывает включение в зачёт).

Серверные примеры для проверки: завершённый 2–1 → +1 к `xOneCount`;
завершённый 2–0–1 → +1; дроп с 1–1 → +0; 2–1 с победой BYE и завершением
всех раундов → +1. Во всех случаях участие остаётся посещением.

## Проверки локального расчёта

- Игрок с низким общим местом проходит по бонусам; это видно в его статусе.
- Победитель Store Championship без дейликов есть в группе финалистов.
- Пересечение двух Store Championship переносит слот в отбор по очкам.
- Пересечения между статистическими квотами не дают повторов и не теряют слоты.
- При равенстве всех тай-брейков на границе слот не выдаётся произвольно.
- Несыгранный ноябрьский турнир сохраняет четыре ожидающих слота.
- Статистика доступна игроку вне финала и с нулём бонусов.
- Суммы очков и посещений не меняются при переключении режима отображения.
